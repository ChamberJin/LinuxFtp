## 快速开始

```bash
git clone https://github.com/ChamberJin/LinuxFtp.git
cd LinuxFtp

python3 -m venv .venv
TMPDIR=$PWD/.tmp .venv/bin/pip install -r requirements.txt

./run.sh                     # 有书签/最近连接时先弹启动页
./run.sh --no-start          # 跳过启动页，直接进主窗口
./run.sh --host ftp.example.com --user bob --password yourpass --port 21
./run.sh --local /var/www    # 指定本地栏初始目录
./run.sh --protocol sftp --host 192.0.2.10 --user deploy --keyfile ~/.ssh/id_ed25519
```

> 注意：部分发行版 `/tmp` 只有 10MB，pip 解包会报"设备上没有空间"。
> 本工程统一用 `TMPDIR=$PWD/.tmp` 规避，`run.sh` 已内置该设置。

## 打包为可执行文件

不想装 Python 环境的话，一条命令打出独立可执行文件：

```bash
.venv/bin/pip install pyinstaller   # 首次
./build.sh
```

产物在 `dist/LinFTP/`，主程序是里面的 `LinFTP` 可执行文件，
整个目录拷到其他机器（无需 Python）也能跑，命令行参数与 `run.sh` 一致。

| 设计点 | 说明 |
|---|---|
| 目录模式而非单文件 | onefile 运行时要把上百 MB 解压到 `/tmp`，在小 `/tmp` 机器上必然失败（本工程专门处理过的坑）；目录模式直接加载、不碰 `/tmp`，启动更快 |
| 产物瘦身 | `build.sh` 内置两步：`strip` 掉 libpython 等库的调试符号（本机托管 Python 自带符号可达 200M+）+ 剔除 Qml/Quick/VirtualKeyboard/Pdf 等纯 Widgets 应用用不到的 Qt 库，423M → 约 193M |
| 资源文件 | `assets/` 由 `--add-data` 带进包内，`theme.py` 按 `__file__` 相对路径取图标，PyInstaller 解包目录下同样成立 |
| 排除大模块 | WebEngine / Qml / Quick / 多媒体 / Sql / tkinter 等在打包参数里显式排除 |

> 单文件模式想要的话把 `--onedir` 换成 `--onefile` 即可，但在 `/tmp`
> 很小的机器上运行时会解压失败，需配合 `TMPDIR` 指到空间足够的目录。

## 图标与桌面入口

一条命令装好图标和桌面快捷方式：

```bash
bash tools/install_icon.sh
```

脚本做三件事（幂等，重复执行只覆盖、不堆重复项）：

1. 用 `rsvg-convert` 把 `assets/linftp-icon.svg` 渲染成
   16 / 22 / 24 / 32 / 48 / 64 / 96 / 128 / 256 / 512 十档 PNG，
   装进 `~/.local/share/icons/hicolor/<尺寸>/apps/linftp.png`；
   再把 SVG 放一份到 `scalable/apps/`，高分屏缩放时不糊。
2. 写 `~/.local/share/applications/linftp.desktop`（启动器可见）
   和 `~/Desktop/linftp.desktop`（桌面双击）。两者 `chmod 755`
   并打上 `metadata::trusted`，否则 DDE/GNOME 双击只弹属性框。
3. 刷新 `gtk-update-icon-cache` 与 `update-desktop-database`。

`Exec` 指向工程的 `run.sh`，虚拟环境与 `TMPDIR` 都沿用同一套逻辑，
不需要另写启动脚本。

### 图标设计

语义是"双栏 + 双向传送"：左侧面板标题条用本地侧的绿（`#0F7A63`）、
右侧用远端侧的蓝（`#3D7BF5`），中间白色徽标里一蓝一绿两个箭头，
对应上传 / 下载两个方向。配色直接取 `theme.Palette`，和程序界面一致。

小尺寸是难点：桌面图标常见 32px 甚至 24px，细节多了会糊成一团。
第一版每栏三个条目 + 小圆点，32px 下完全看不出结构；最终版把条目
减到三个、加粗条形、放大中心徽标，16px 仍能辨认出双栏轮廓。

> 调试技巧：改完 SVG 立刻渲染多档尺寸并排看，别只看 256px。
> 判断图标是否"空"要看 `pixmap()` 能不能渲出像素，
> 不能看 `availableSizes()` —— 对 SVG 图标它天然返回空列表。

### 窗口图标与任务栏归组

`__main__.py` 里设了 `app.setDesktopFileName("linftp")`，与
`.desktop` 的 `StartupWMClass=linftp` 对齐，任务栏才会把窗口归到
应用图标下，而不是显示成一个无图标的窗口。

应用图标本身由 `theme.app_icon()` 提供，在 `theme.apply()` 里
一次 `app.setWindowIcon()`，所有窗口和对话框自动继承——不用在
四个 `setWindowTitle()` 旁边各补一行。查找顺序：
`QIcon.fromTheme("linftp")` → hicolor 里的 SVG/PNG →
工程内 `assets/linftp-icon.svg`（源码目录直接跑的情况）。

## 启动页

程序启动时，如果**有书签**或**最近连过服务器**，会先弹出启动页：

- 列表里混排「书签」与「最近连接」，本地书签在前、远端书签在后，
  最近连接排在最后（与之同站点的远端书签已存在时自动去重，不会出现两次）。
- 顶部搜索框输入即过滤，名称、路径、站点地址都能匹配。
- **双击 / 回车 / 点「打开」** 直接进入：本地书签跳目录，远端书签自动建连再跳。
- **Esc / 「跳过」** 进空白主窗口，手动连接。
- 没有任何可选项时不弹（也可以用 `--no-start` 强制不弹，
  或 `--host` 直接连接时绕过）。

「最近连接」在每次连接成功后自动记录（只存协议/主机/端口/账号，
**不存口令**），上限 10 条，存在 `sites.json` 的 `recents` 字段里。
从启动页点最近连接时，会先去站点库找同站点的配置补口令；
找不到才弹连接框让用户输一次。

### 启动时默认打开某个书签

不想每次启动都在启动页上点一下的话，可以在**书签管理**里选中某条，
勾上「启动时默认打开选中的书签」。之后启动就直接连上去，不再弹启动页。

- 全局只能有一个默认项，勾新的会自动取消旧的（`auto_open` 字段，
  存在 `bookmarks.json` 里）。
- 默认项在书签列表和工具栏菜单里都带 `★` 前缀，一眼能看出为什么这次没弹启动页。
- **兜底比功能本身更重要**：默认书签失效、缺口令、连不上时，
  都静默退回启动页，不会拿一个连不上的书签把人挡在门外。
  缺口令时也不弹连接框——启动瞬间问密码比直接给启动页更难理解。

## 界面主题

所有样式集中在 `linftp/theme.py`，改一处即整体换肤：

- `Palette`：颜色常量（底色、卡片、描边、主色、本地侧点缀色、危险色…）
- `icons()`：18+ 个线性图标，用内嵌 SVG 在运行时按主题色渲染成 QIcon，
  **不依赖任何图片资源文件**，也不怕高分屏缩放
- `qss()`：统一 QSS。ComboBox 箭头、CheckBox 勾、SpinBox 上下箭头
  都在运行时生成到临时目录再被 QSS 引用

视觉取向：浅色底 + 卡片式分区（`Card` 类）+ 柔和描边 + 悬停反馈。
工具栏图标与文字并排、按功能分组；两侧面板各有侧别色标
（本地绿、远端蓝），本地/远端一眼可分。
状态栏用一个小圆点表示连接状态（灰=未连接，绿=已连接）。

## 紧凑模式

工具栏最右侧的 **标准 / 紧凑** 按钮，或快捷键 **Ctrl+Shift+M** 切换：

| | 标准模式 | 紧凑模式 |
|---|---|---|
| 文件行高 | 26px | 21px |
| 一屏可见文件（1180×720） | 约 10 行 | 约 15 行 |
| 路径框 / 过滤框 | 30 / 28px | 25 / 24px |
| 导航按钮 | 30px | 25px |
| 卡片内边距 | 10,8,10,10 | 6,4,6,6 |
| 工具栏图标 | 17px | 15px |
| 两侧分栏手柄 | 8px | 5px |
| 状态栏高度 / 圆点字号 | 24px / 12px | 19px / 11px |
| 时间 / 权限列宽 | 132 / 104 | 124 / 96 |

实现方式：所有像素值集中在 `theme.Metrics`（`STANDARD` / `COMPACT` 两套），
`Card`、`FilePane` 各自实现 `apply_metrics()` 重排自己，
QSS 也由 `qss(metrics)` 生成。切换时：

1. 先记下两处分栏的**比例**，再换规格、重刷 QSS、逐件重排；
2. 按比例还原分栏，用户手动拖过的宽度不会被重置成 1:1；
3. 日志展开状态、队列自适应高度跟着重算；
4. 选择写入 `~/.config/linftp/ui.json`，下次启动直接沿用。

启动页也会跟随同一个模式（行高 56 → 40），状态栏同理（24 → 19px）。

> 注意：紧凑模式只收窄**冗余留白**，不压字号。
> 列宽是按实测文本宽度定的（`2026-11-16 15:06` 约 102px），
> 收得再狠就会出现省略号。状态栏同理：13px 字体配 19px 高度，
> 上下各剩 3px，再压就会切字。

### 状态栏为什么曾经压不下去

`QStatusBar` 原本不在 `Metrics` 体系里，QSS 只写了 `padding: 2px 4px`，
高度完全由 Qt 默认的 24px 决定——两种模式一模一样，紧凑模式下
底部那条显得特别厚，像是"漏改了"。

修法是把它纳入同一套规格：`Metrics.statusbar_h` 决定高度，
`statusbar_dot_size` 决定连接圆点字号，QSS 里用
`min-height` / `max-height` 双向锁死（只写一个方向时，
`QStatusBar` 的 sizeHint 仍会把它撑回 24px）。
切换模式时 `MainWindow.apply_statusbar_metrics()` 重新
`setFixedHeight` 并重设圆点字号——圆点是 QLabel，
字号得单独设，QSS 的 `QStatusBar` 规则管不到它。

### 已修复的坑：重启后紧凑模式"只对一部分生效"

最早的实现里，`theme.apply()` 在 `__main__` 中**先**按标准规格生成了 QSS，
而 `MainWindow.__init__` **后**才 `set_compact(pref)` 换掉 `Metrics`。
换规格时只改了模块级 `metrics` 变量，没人重新生成 QSS —— 于是图标缩到了
15px、表格行高压到了 21px，但 `QToolButton` 的 padding 还是标准的
`5px 9px`，工具栏高度一动不动。看起来就是"重启后紧凑模式对工具栏无效"。

修复要点（三处，都在 `theme.py` / `mainwindow.py`）：

| 问题 | 修法 |
|---|---|
| `set_compact()` 只换 metrics、不换 QSS | 让 `set_compact()` **自己负责** `app.setStyleSheet(qss())`，任何调用方都不用记得手动刷 |
| `QToolBar` 一旦 `setIconSize` 过，就**不再跟随** `QMainWindow.setIconSize()` | `_apply_toolbar_metrics()` 里遍历 `findChildren(QToolBar)` 逐个同步，否则只有重启才跟得上 |
| `QDialog` 的字体是**构造时**从父窗口快照的，`app.setFont()` 之后不再传入 | 新增 `theme.inherit_app_font(widget)`，在 `LaunchPad` / `ConnectDialog` / `BookmarkDialog` 构造末尾显式同步 |

顺带把散落各处的写死数值（书签按钮图标 17px、"编码"标签 12px、
启动页副标题 12px）统一改成跟随 `Metrics`。

## 多屏摆位

内置屏与外接屏的逻辑坐标往往差得很远（本机实测内置屏 `eDP-1` 在
`(775, 2160)`、外接屏 `DP-1` 在 `(0, 0)`，缩放都是 1.5）。顶层窗口第一次
上屏时，屏幕是由窗口管理器挑的，**不受 Qt 控制** —— 主窗口开在副屏、
跟着居中的启动页又落到主屏，就成了"两个窗口各占一块屏"。

`theme.py` 里给了三个函数，构造上屏流程时按顺序用：

| 函数 | 用途 |
|---|---|
| `place_on_primary(win)` | 主窗口**首次上屏前**摆到主屏居中，避免 WM 乱挑屏 |
| `center_on_parent(dlg, win)` | 把弹窗相对父窗口居中，并收进父窗口所在那块屏的可用区 |
| `keep_on_screen(w)` | 兜底：窗口位置落在已拔掉的显示器上时拉回来 |

`center_on_parent()` 内部会先 `layout().activate()` 再取尺寸 —— 必须在
`show()` 之后、布局定型了才调，否则拿到的是初始尺寸，居中会算歪。
`LaunchPad` 另外在 `showEvent` 里再校正一次，覆盖窗口管理器在真正映射
窗口时的擅自挪动。

> 同一套代码在两块屏上都会执行；`tools/test_screen.py` 在单屏下跑坐标
> 算法，多屏下额外跑一次"主窗口与启动页是否同屏"的端到端断言。

## 窗口大小 / 位置记忆

退出时把主窗口的大小、位置和最大化状态写进 `~/.config/linftp/ui.json`，
下次启动按记录还原；没有记录才退回"主屏居中"。

```json
{
  "compact": true,
  "window": { "x": 1240, "y": 2470, "w": 1119, "h": 700, "maximized": false }
}
```

几个必须处理好的点：

| 情况 | 处理 |
|---|---|
| 最大化时退出 | 存 `normalGeometry()` 而非 `geometry()`，否则取消最大化后还是满屏 |
| 记录的位置已经不在任何屏上（拔了外接屏） | 按中心点反查屏幕失败 → 放弃记录，改走 `place_on_primary()` |
| 换了更小的屏，原尺寸装不下 | 先缩到该屏可用区，再把位置收进屏内 |
| 文件损坏 / 缺字段 / 存成 0 尺寸 | 一律当作"没存过"，不让程序起不来 |
| 与紧凑模式偏好共存 | 整份读出来改一个键再整份写回，互不覆盖 |

写法上是"先写临时文件再 `os.replace()`"，写到一半崩掉不会留下半截 JSON
把下次启动的偏好读崩。

## 常驻托盘

关窗口不再等于退程序：上传跑到一半顺手把窗口关掉，进程还在，任务接着跑。

关闭时如果没记过偏好，会先问一次：

| 选项 | 结果 |
|---|---|
| **最小化到托盘**（默认） | 窗口藏起来，连接、保活定时器、传输队列全保留 |
| 退出程序 | 断开连接、停队列、结束进程 |
| 取消 | 什么都不做，窗口留着 |

> 默认按钮放在「最小化到托盘」上：误按回车不至于把正在跑的任务掐掉。

- 勾上「记住我的选择」后不再询问，选择写进 `~/.config/linftp/ui.json` 的
  `close_action`（`tray` / `quit`）。
- 想改回来：托盘菜单里取消勾选「关闭窗口时收进托盘」，下次关闭又会问。
- 有任务没跑完时选「退出程序」，还要再确认一次（`仍有传输任务`），防止手滑。

托盘菜单：

| 菜单项 | 作用 |
|---|---|
| 连接状态（灰色不可点） | 「未连接」或「已连接 FTP u@h:21 · 2 个任务传输中」 |
| 打开主窗口 | 左键单击 / 双击托盘图标同效；最小化过会先还原 |
| 断开连接 | 与工具栏「断开」一致，未连接时置灰 |
| 关闭窗口时收进托盘 | 勾选即记住；取消勾选恢复「每次询问」 |
| 退出 | 先把窗口亮出来再关，有任务时照样二次确认 |

收在托盘期间传输跑完，会用系统通知告知结果；一次拖多个文件只在**队列全空**时
提示一次，不逐条刷屏。

### 没有托盘的桌面

`QSystemTrayIcon.isSystemTrayAvailable()` 为假（没装托盘扩展的桌面、只有裸 X
的远程会话）时不提供「收进托盘」这个选项，关闭动作一律按「退出」走 ——
否则窗口一藏就再也没有入口了。

自动化测试里没人点按钮，统一用 `LINFP_NO_TRAY=1` 关掉托盘，
免得关闭时弹出询问框把用例卡死：

```bash
LINFP_NO_TRAY=1 .venv/bin/python tools/test_tray.py
```

### 两个必须处理好的地方

| 坑 | 处理 |
|---|---|
| 最后一个窗口藏起来后 Qt 会顺手退出程序 | 起托盘时 `setQuitOnLastWindowClosed(False)`，退出只留「明确选退出」和「托盘菜单退出」两个入口 |
| 传输队列在工作线程里回调，托盘气泡却只能在 GUI 线程发 | 回调先转成 `task_updated` 信号排队回主线程再动界面（顺带修掉队列表格跨线程刷新的老问题） |

另外：`QMessageBox` 自己定尺寸，`setMinimumWidth()` 会被忽略，想把说明文字
放宽只能设它的 `qt_msgbox_informativelabel` 最小宽度 —— 不然「最小化到托盘」
那行会折得很难看。

## 列表排序

点表头任意一列就能排，再点一次切降序。表头右侧的箭头指示当前排序列与方向。

| 列 | 排序依据 | 备注 |
|---|---|---|
| 名称 | 文件名 | 不区分大小写，`A.txt` 排在 `b.txt` 前 |
| 大小 | 真实字节数 | 不是 "1.5 KB" 这种显示文本 |
| 类型 | 类型文字 | |
| 修改时间 | 时间戳 | 不是格式化后的字符串 |
| 权限 | 权限位 | 拿不到权限的（FTP 常见）排最前 |

- **目录永远在最上面**，升降序只作用于文件之间（跟 WinSCP 一致）。
- 排序状态**跟着面板走**：切目录、刷新、过滤都不会重置回默认。
- 排序后**选中项不丢**：按路径重新定位选中行和当前行，不会因为重排就清空选择。
- 两个栏各自独立排序，本地和远端互不影响。

> 大小如果按显示文本排，会出现 `900 B` 排在 `1.5 KB` 后面；时间按文本排，
> 未知时间显示的 `-` 会插到中间。所以排序键单独写了一份（`models.sort_key()`），
> 显示归显示、排序归排序。

## 文本预览

双击任意文件打开只读预览窗口，右键菜单里也有「预览」。

- **只读前 2 MB**。远端只拉文件头部：SFTP 直接 seek，FTP 收到够数就主动中止，
  不会为了看一眼日志把几百兆全下载下来。超限时提示里写明「仅显示前 2 MB」。
- **编码自动探测**：UTF-8 → GB18030 → Big5 → latin-1 依次试，UTF-16/32 按 BOM
  识别；探测不准就在顶部下拉框手动指定，不用重开窗口。
- **二进制不塞乱码**：含 NUL 或大量控制字节时只显示一句「这不是文本文件」，
  本地文件另外给一个「用系统程序打开」的出口。
- **Ctrl+F 查找**，回车找下一个，命中行滚到屏幕中间并显示「第 N 处匹配」。
- 「自动换行」可切换，默认不换行——日志的列对齐不会被破坏。

> 截断点可能正好切在多字节字符中间。直接解码会让好好的 UTF-8 解码失败、
> 被误判成 GBK 显示乱码，所以 `decode_text(may_truncate=True)` 会先把尾部
> 1~3 字节切掉再试。

`preview.py` 里 `guess_text_kind` / `looks_binary` / `decode_text` 都是纯函数，
测试直接打它们，不依赖界面。

## 右键菜单导航

面板顶上那两个小图标（上级目录 / 主目录）和工具栏的「刷新」，在**右键菜单最上面**
也有一份 —— 手正放在列表上时，不用再挪回面板顶部去找按钮：

| 菜单项 | 本地面板 | 远端面板 |
|---|---|---|
| 上级目录 | 回上一层；已经在 `/` 时置灰 | 同左，按当前远端路径逐层往上 |
| 主目录 | 回到 `~` | 回到 `/` |
| 刷新 | 只重读本地这一侧 | 只重读远端当前目录 |

- 这三项**不看落点**：右键点在文件名上、点在列表空白处都一样能用，
  不必先选中任何行。
- 右键刷哪侧就只刷哪侧；工具栏那个「刷新」（Ctrl+R）仍然是两侧一起刷。
- 远端没连上时三项一起置灰 —— 不给"点了之后什么都不发生"的按钮。
- 菜单里其余操作（上传 / 下载 / 新建 / 重命名 / 删除 / 收藏）保持原样可点，
  未连接时由它们自己提示，菜单不替它们提前拦。

## 复制路径

两侧面板的右键菜单里，导航组下面就是「复制路径」，快捷键 **Ctrl+Shift+C**
（列表有焦点时生效，不跟 Ctrl+N / Ctrl+R / Ctrl+D / Ctrl+B 抢）。

| 你在做什么 | 复制到的内容 |
|---|---|
| 选中一项，右键「复制路径」 | 该项绝对路径，如 `/srv/app/app.log` |
| 选中多项 | 每行一条，顺序与列表一致 |
| 右键点在**未选中**的行上 | 只复制那一行（不会拿上一次的多选去复制） |
| 右键点在列表空白、且没有选中 | 当前目录路径，文案自动变成「复制当前目录路径」 |

- 远端栏复制的是服务器上的路径（`/srv/app/...`），本地栏是本地路径
  （`/home/you/...`），都**不带主机名**，粘到终端、配置或聊天里能直接用。
- 菜单文案会跟着条数变（`复制路径` / `复制 3 项路径` / `复制当前目录路径`），
  按之前就能看出会复制什么。
- 复制完只在**状态栏**给一句 `已复制路径：…`，2.5 秒后自散；
  不写日志面板——复制是高频操作，别把日志刷满。
- 重复路径自动去重，空路径不写剪贴板，也不会把已有剪贴板内容清掉。

> 状态栏提示是**延后一帧**写的：右键菜单关闭时主窗口会收到一个空的
> `StatusTip` 事件，顺手就把状态栏消息清掉，当场写等于没写。
> 这个坑只在"从菜单里点"的路径上出现，用快捷键复制看不出来。

## 路径栏层级跳转

路径栏还是原来的样子（只读输入框），但**路径里的每一层都能点**：
停在 `/项目文档/BUILD7.0/终版归档` 时点中间的 `BUILD7.0`，直接跳到
`/项目文档/BUILD7.0`，省得一路按「上级目录」。

| 点哪里 | 跳到哪里 |
|---|---|
| 最左边的 `/` | 根目录 |
| 中间任意一层 | 该层目录 |
| 最末层（就是当前目录） | 不动，也不会白刷一次列表 |
| 分隔符 `/` 本身 | 算它**左边**那一层 |

- 鼠标移到路径上会变**手型**，并提示「点击跳到 /…」，不用记快捷键。
- 本地栏跳本地、远端栏跳远端（远端走的就是正常目录切换，会重新列目录）。
- 长路径固定**从左边开始显示**（这样根和上层都点得到），末尾放不下就裁掉——
  当前目录名在右边列表里本来也看得到。
- 路径栏不参与键盘焦点：点完不会留一个蓝色聚焦框，也不会把焦点从文件列表上抢走，
  想接着按 Ctrl+Shift+C 复制路径照样好使。

> 为什么不做成面包屑按钮串：`/项目文档/BUILD7.0/终版归档/子目录/…` 这种长路径
> 在双栏布局里会挤爆面板宽度，还得自己做折叠；输入框天生会裁剪，长路径也不难看。

## SFTP

连接对话框里把「协议」切成 `sftp`，端口自动从 21 变 22（手填过端口就不会被覆盖），
「被动模式」和「文件名编码」两行会隐藏 —— SFTP 没有这两个概念。

| 认证方式 | 填法 |
|---|---|
| 密码 | 用户名 + 密码，「私钥文件」留空 |
| 私钥 | 「私钥文件」选 `~/.ssh/id_ed25519`（OpenSSH / PEM 都行），密码可留空 |

几个行为：

- **默认用户名跟着协议走**：切到 sftp 时若还是 `anonymous` 会自动变 `root`；
  手动改过就不再动它。
- **主机密钥**：优先信任 `~/.ssh/known_hosts` 里已有的记录；第一次连某台机器时
  自动信任，`SHA256:` 指纹记在会话对象的 `host_key_fingerprint` 上，需要严格
  校验时可以连上后核对。
- **编码**：文件名固定 UTF-8，工具栏的编码下拉框会置灰。
- **续传**：用文件句柄 seek 实现，不依赖服务端 `REST`；上传续传时若远端文件已被
  删掉，会自动退回整传。
- **chmod 直接可用**，不像 FTP 那样要看服务端是否支持 `SITE CHMOD`。
- **私钥格式**：PEM 与 OpenSSH 都能读；带口令的私钥暂不支持在界面里输入口令
  （可以先 `ssh-add` 到 ssh-agent，界面留空私钥走 agent）；PuTTY 的 `.ppk`
  需要先 `ssh-keygen -i` 转成 OpenSSH 格式。

命令行等价写法：

```bash
./run.sh --protocol sftp --host 192.0.2.10 --user deploy --keyfile ~/.ssh/id_ed25519
./run.sh --protocol sftp --host 192.0.2.10 --user deploy --password '...' --port 2222
```

> SFTP 依赖 `paramiko`（已写进 `requirements.txt`）。其余功能与 FTP 完全一致：
> 双栏浏览、传输队列、书签、启动页、右键复制路径、路径栏跳转都能直接用。

## 书签

工具栏「书签」按钮直接下拉，点任意一条即跳到对应目录。

| 操作 | 入口 |
|---|---|
| 打开书签跳转 | 工具栏「书签」菜单 / 右键「打开书签…」/ Ctrl+B 管理框内双击 |
| 添加当前目录 | Ctrl+D，或右键「收藏当前目录为书签…」，或菜单内底部两项 |
| 管理（重命名/排序/删除） | Ctrl+B |

**设计要点**：

- 书签分 **本地** 与 **远端** 两侧，互不干扰。本地书签点了立即跳转；
  远端书签会检查当前连接，**站点不同就自动建连再跳转**。
- 远端书签**记住口令**，存盘时用机器绑定的密钥做可逆混淆
  （`enc:` 前缀），配置文件里不出现明文。换机器后旧口令自然失效，
  会提示重输——这是刻意的安全取舍。
- 同一侧同路径重复收藏视为同一书签，只更新名称，不会堆重复项。
- 本地目录被删除后点书签，只在日志和状态栏提示，**不弹阻塞窗口**，
  避免自动化或批量跳转被卡住。

## 文件名编码（重要）

国产化 FTP 服务器常见 GBK 文件名，而 ftplib 默认按 utf-8 解码控制连接，
一遇到 GBK 字节就抛 `UnicodeDecodeError`，整个目录打不开。

**本工程的处理方式：**

1. **控制连接固定用 `latin-1` 传输。** 它与字节 0-255 一一对应，收发都
   不会抛异常，把解码失败的可能性彻底移出 ftplib 内部。
2. **真实编码在应用层处理。** 所有路径经 `_abs()` 统一编码成 wire 形式，
   所有服务端返回的名字经 `_decode_name()` 还原。
3. **连接后自动探测编码。** 拿一次原始列表，依次尝试
   `utf-8 → gbk → gb18030 → big5`，第一个能把**全部**文件名严格解通的即为命中。
   用户显式指定的编码若能解通则优先尊重。
4. **兜底绝不崩溃。** 探测失败或编码选错时退回 `errors="replace"`，
   最差情况是某个文件名显示为乱码，而不是整个目录不可用。
5. **工具栏可手动切换。** 出现乱码时下拉选具体编码，立即刷新当前目录。

### 已修复的坑：切换编码后报 `error_reply: 200 Type set to A.`

这是 FTP 的**响应错位**问题，成因链：

1. 编码探测原先用 `self._cwd` 拼命令，而 `_cwd` 存的是**已解码的界面路径**
   （可能是中文）。中文无法通过 latin-1 发出，`retrlines` 在发命令时就抛异常。
2. 异常发生在 `TYPE A` 已发出、数据连接已建立的**中间状态**，控制连接里
   留下未读的响应行。
3. 下一条命令读到了上一条的 `200 Type set to A.`，报错。

**修复三重保障：**

| 措施 | 作用 |
|---|---|
| 探测固定列根目录 `/` | 纯 ASCII，任何编码下都安全，不再用中文 cwd 拼命令 |
| `_resync()` 清理残留响应 | MLSD/LIST 任何失败后主动读空控制连接缓冲区，杜绝错位 |
| `_to_wire()` 失败即报错 | 明确抛「无法用 X 编码发送，请切换编码」，不再让底层异常炸掉连接 |

FTP 是严格一问一答的协议，**任何一次传输中途失败都必须清理控制连接**，
否则下一条命令必然读到上一条的响应。这条规则适用于所有 FTP 操作。

## 关键设计

**统一接口，协议可插拔。** `backend/base.py` 定义 `FtpSession`，
上层 UI 和队列只依赖它。接 SFTP 时只新增了 `backend/sftp.py`
并在工厂里加了一个分支，UI 侧仅补了协议下拉和两行显隐 ——
抽象层省掉的正是这部分重复。

**传输全部在后台线程。** 每条任务独立建连（FTP 控制连接非线程安全，
共享会串包），任务状态通过回调推给 UI，主线程只渲染。

**续传要判定，不能只看文件存在。** 只有当"已有部分数据且小于完整文件"
时才续传，否则从 0 开始覆盖，避免拼接出损坏文件。

**目录列表优先 MLSD。** MLSD 是 RFC 3659 的结构化格式，避免解析
`ls -l` 文本时的中文名、时间格式、各种服务端方言问题；仅在服务端
不支持时回退 LIST，且同时兼容 Unix 与 DOS 两种文本格式。

## P0 阶段已知的踩坑记录

1. **FEAT 是多行响应，必须读完整个段落。**
   用 `sendcmd("FEAT")` 只会读第一行，剩余行留在 socket 缓冲区，
   导致后续所有命令错位吞掉上一条的响应（PASV 收到 200、MKD 收到 257）。
   正确写法：`putcmd("FEAT")` + `getmultiline()`。
   也不能用 `retrlines("FEAT")` —— 它会去建数据连接，直接超时。

2. **`storbinary` 需要带 `read()` 的文件对象，不能传生成器。**
   已用 `_ProgressReader` 包装，同时完成进度上报与取消检查。

3. **部分服务端 MLSD 不给 `unix.mode`，只给 `perm=elradfmwMT`。**
   这类 perm 是功能语义，不含 owner/group/other 区分，
   代码里做了近似映射，**仅用于界面展示，不能当真实权限用**。

4. **中文文件名**依赖 `TYPE I` + UTF-8 编码。老服务端需把
   文件名编码切成 gbk，连接对话框已提供选项。

5. **`open_bookmark` 里不能用阻塞式 `QMessageBox` 报错。**
   书签失效是常见情况（目录被删、服务器下线），弹窗会阻塞调用方；
   在自动化/批量跳转场景下直接卡死进程。改为写日志 + 状态栏提示。
